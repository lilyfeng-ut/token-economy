Design briefs

How each lever works.

Implementation briefs—not vendor prescriptions. Each method names the decision boundary, minimum data contract, guardrails, and evidence needed before scaling it.

Design contract

  • Fingerprint normalized intent, tool state, permissions, locale, and answer schema.
  • Retrieve exact first, then semantic candidates inside the same policy partition.
  • Gate on similarity, freshness, source version, determinism, and data scope.

Prove it

  • Measure useful hit rate, false-hit severity, avoided cost, and added latency.
  • Start read-only with shadow decisions; calibrate thresholds per intent class.
  • Placeholder: vector store, embedding model, invalidation events, and TTL matrix.

Decision sequence

  • Apply hard gates for modality, context, region, privacy, and tool support.
  • Predict quality, latency, total completion cost, and failure probability.
  • Select from the Pareto frontier under the task’s service-level objective.

Prove it

  • Use replay sets, online holdouts, regret, escalation rate, and task success.
  • Fallback on timeout, refusal, low confidence, or verification failure.
  • Placeholder: feature schema, model catalog, scorer, and exploration policy.

Pipeline

  • Separate instructions, working memory, retrieved evidence, and tool state.
  • Rank by marginal answer value; deduplicate and compress below a token budget.
  • Preserve citations and lossless facts; summarize only replaceable narrative.

Prove it

  • Plot task quality against tokens removed, retrieval coverage, and truncation loss.
  • Version every transform for traceability and deterministic replay.
  • Placeholder: memory policy, reranker, summarizer, and context manifest.

Policy hierarchy

  • Allocate budgets by tenant, workflow, user, and time window.
  • Reserve capacity for critical paths; degrade optional work gracefully.
  • Estimate full task cost, including tools, retries, verification, and fallbacks.

Prove it

  • Track cost per successful task, rejection quality, burst use, and forecast error.
  • Return explicit defer, downgrade, batch, or reject decisions.
  • Placeholder: quota store, estimator, priority classes, and override workflow.

Risk tiers

  • Assign verification depth from task impact, uncertainty, and reversibility.
  • Use schema checks, evidence checks, deterministic validators, then model judges.
  • Escalate to a stronger route or human review when the risk budget is exceeded.

Prove it

  • Measure escaped defects, false alarms, correction cost, and grader agreement.
  • Keep safety policy independent from model selection and commercial pressure.
  • Placeholder: risk taxonomy, validators, judge prompts, and review queue.

Event model

  • Record request, transforms, cache decisions, route, retries, tools, and outcome.
  • Attribute price at event time and preserve model, prompt, and policy versions.
  • Join technical telemetry to task success, user correction, and business value.

Prove it

  • Lead with value per dollar; use tokens and cache rate as diagnostic metrics.
  • Support trace replay, cohort comparison, anomaly alerts, and unit economics.
  • Placeholder: event schema, pricing snapshots, retention, and value proxies.

Recommended starting point: instrument the economic ledger first, then introduce semantic cache and routing decisions in shadow mode.
